## Evinced remediation guidance

**Cause:**  
    The element lacks proper semantic markup or has incorrect implementation that prevents keyboard accessibility. This commonly occurs when:  
    1. Custom interactive elements are built using non-semantic tags like `<div>` or `<span>` without appropriate ARIA roles.  
    2. Elements intended to be interactive are implemented without semantic meaning (e.g., using `<div onclick="...">` instead of `<button>`).  
    3. Interactive elements have `tabindex="-1"` or other values that improperly remove them from the tab sequence.  
    4. CSS styling removes or obscures focus indicators without providing accessible alternatives.

    **Effect:**  
    The element is excluded from the keyboard tab sequence, making it completely inaccessible to keyboard-only users, including individuals with motor disabilities who cannot use a mouse. This violates WCAG 2.1 Success Criterion 2.1.1 (Keyboard) and prevents assistive technology users from accessing or interacting with the element.

    **Suggested Solutions:**  
Follow these mutually exclusive steps in the required order to restore keyboard accessibility:

1. **Add or correct ARIA roles and keyboard support on non-semantic or incomplete elements**  
   - Apply an ARIA role that reflects the intended interactivity (e.g., `role="button"`, `role="link"`, `role="checkbox"`).  
   - Ensure the element is reachable via keyboard by adding `tabindex="0"` when appropriate.  
   - Implement the required keyboard interaction model based on the role (e.g., Enter/Space activation, arrow keys for widgets).  
   - Provide necessary ARIA states (`aria-expanded`, `aria-pressed`, etc.) to reflect interaction updates.

2. **If the element is using an incorrect native tag for its intended function, replace it with the correct semantic tag**  
   - This step applies only when the element *already uses a native tag*, but that tag does not match its purpose.  
   - Examples:  
     - Replace a `<div>` acting like a button with a `<button>`  
     - Replace a `<span>` used for navigation with an `<a href="…">`  
   - Native elements automatically participate in the tab order and support keyboard activation.

3. **If neither ARIA nor native tag correction is applicable, convert the element into the correct semantic structure**  
   - Rebuild or refactor the component into the appropriate semantic and interactive pattern when the previous steps do not apply.  
   - Example: converting a custom widget to a proper composite component that follows ARIA Authoring Practices.

**Critical Implementation Notes:**  
- Avoid using `tabindex` values greater than `0`, as they disrupt logical tab order.  
- Ensure focus indicators remain visible and meet 3:1 contrast requirements.  
- Always test with real keyboard interaction (Tab, Enter, Space, Arrow keys where relevant).
