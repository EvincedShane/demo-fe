## Evinced remediation guidance

**Cause:**  
The element lacks an accessible name that assistive technologies are using to identify and announce its purpose. An accessible name is a short string (typically 1-3 words) that provides users of assistive technologies with a clear label for the element. This is a fundamental requirement under the WCAG guidelines for all interactive elements.

**Effect:**  
Without an accessible name, screen readers will either announce the element generically (e.g., just "button" without context) or skip it entirely, leaving users unable to understand the element's purpose or predict the outcome of interacting with it. This creates significant barriers for users relying on assistive technologies like screen readers and voice control software, as they cannot effectively navigate or use the interface.

**Suggested Solutions:**  
Implement accessible names using these methods in order of preference:

1. **Visible text content**: Use descriptive text within the element (e.g., `<button>Submit Form</button>`).  
2. **aria-label**: Add descriptive label directly (e.g., `<button aria-label="Close dialog">×</button>`).  
3. **aria-labelledby**: Reference existing descriptive text by ID (e.g., `<button aria-labelledby="save-btn-text">`).    
4. **Form labels**: For `<input>` elements use explicit `<label>` elements or `aria-label` for form controls.  

**Critical Implementation Notes:**  
- **Verify uniqueness**: Before applying an aria-label, search the codebase/DOM for that exact label text to ensure it's not already in use on a different element. Each interactive element must have a label that distinguishes it from all other elements on the page.  
- **For multiple similar elements** (e.g., multiple navigation regions): Add specific location or purpose descriptors:
  - GOOD: "Top navigation", "Sidebar navigation", "Footer navigation".  
  - BAD: "Main navigation" (used for multiple navs)  
  - GOOD: "Primary search", "Header search", "Product search".
  - BAD: "Search" (used for multiple search inputs)  
- Names should be meaningful and descriptive enough to convey both purpose and expected outcome.  
- Avoid generic terms like "click here," "button," or "link" — be specific about the action.  
- For icon-only buttons, always provide text alternatives even if icons seem self-explanatory.  
- **Verification step**: After applying labels, check that no two interactive elements on the page share the same aria-label or accessible name.  
- Test with actual screen readers to verify the accessible name is announced as expected.
